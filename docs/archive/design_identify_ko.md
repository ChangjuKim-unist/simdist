# 설계 문서 10: Identify, don't imitate — 실데이터의 역할을 "모델 학습"에서 "물리 식별"로

작성 2026-10-29. 선행: 설계 문서 6(커버리지는 prior), 7(결합은 모델·prior 갱신 모두에 적용; 잔차·증류 불성립), 9(배포 분포 정합 가중, 진행 중). 사용자 결정: 이 방향으로.
컨셉: SimDist의 "실데이터 → 잠재 동역학 미세조정"이 결합과 커버리지 벽의 뿌리다. 학습된 잠재 모델은 수집 정책에 묶이지만 **시뮬레이터는 정책과 무관**하다. 실데이터로 시뮬의 물리 파라미터를 식별하고, (i) 그 값을 중심으로 DR을 잡아 prior를 시뮬에서 재학습하며, (ii) 월드모델 동역학은 식별된 시뮬에서 **배포 prior로 생성한 on-policy 데이터**로 적응한다(수집 정책 = 배포 정책, 양 무제한). 시뮬이 못 담는 잔여만 실데이터 잔차로 마지막에 보정한다.

## 1. 식별기 (정책 독립)
실로그의 짧은 구간(K = 10스텝, 0.2 s)마다: 시뮬 로봇을 로그 상태(관절 위치·속도, 몸체 각속도·선속도, 중력 벡터→롤·피치, 발 운동학으로 높이)로 리셋 → 로그 행동을 열린 루프로 K스텝 적용 → 예측 고유수용 관측과 로그의 차(표준화 MSE, 처음 2스텝 제외). 로봇마다 다른 후보 모터 스케일(0.2–1.2, 21점 × 18대). 후보별 평균 오차 → 우도(DROPO식) → MAP·사후평균. 정책·월드모델·히스토리 특징을 쓰지 않으므로 **누가 모은 로그든 같은 추정**이 나와야 한다. 구현: `scripts/sim2sim/identify_physics.py`.

## 2. 예측 (실험 전 기록)
- **P10a (정확도)**: prior-first 모터 0.4 로그 → MAP ∈ [0.3, 0.5]; 정상 로그 → MAP ∈ [0.85, 1.1].
- **P10b (정책 독립)**: 좁은 prior 로그(SimDist 계획기, 넘어짐 많음)에서도 MAP ∈ [0.3, 0.5] — 설계 문서 5의 히스토리 가시성(R² 0)과 대비: 식별은 정책이 아니라 시뮬레이터가 한다.
- **P10c (하드웨어, 세션 전 기록)**: Go1 토크 60 %·40 % 로그에서 MAP이 각각 0.6·0.4의 ±0.15 안. 정상 로그에서 실제 Go1의 유효 모터 스케일 추정(참값 없음; 재현성만: 세션 간 ±0.1).
- **P10d (적응 대체)**: 식별된 시뮬(MAP)에서 배포 prior로 생성한 45k 데이터로 적응한 동역학 ≥ 실데이터 prior-first 적응(B′), 그리고 좁은 로그에서 출발해도 같은 결과(결합 없음). 시뮬-투-시뮬에서는 MAP ≈ 0.4이면 이 데이터가 prior-first 데이터와 같은 분포이므로 B′(0.93)로 재현되는지만 확인.

## 3. 관문
P10a·P10b 성립 → 하드웨어 세션에 식별 단계 추가(각 조건 로그 1분 → MAP → 세션 후 식별 시뮬로 prior 재학습·동역학 적응 → 다음 세션 M6). P10a만 성립(정책 의존) → 식별은 prior-first 로그 한정으로 축소. 둘 다 불성립 → 설계 문서 9의 가중 방식이 방법.

## 4. 위험
- 임의 상태 리셋의 접촉 불일치(발 관통·높이 오차) → 처음 2스텝 제외, 발 운동학 높이; 그래도 안 되면 K를 5로.
- DCMotor의 effort_limit만 스케일(평가 조건은 saturation_effort도 스케일) → 저속에서는 동일, 고속 차이는 작음; 결과에 명시.
- 마찰·질량은 이번 식별 격자에 없음 → 모터 1축으로 시작, 성립하면 3축 격자(21 × 5 × 5 = 525대).

## 5. 결과 1차 (2026-10-29 16:30) — 식별기 v2 (토크 요구 가중, 관절 공간, 0.4 s 구간)
| 로그 (수집 정책) | 참값 | v1 MAP | **v2 MAP / 사후평균** |
|---|---|---|---|
| prior-first 모터 0.4 (넓은 학생 + 계획기) | 0.40 | 1.00 | **0.50 / 0.51** |
| 좁은 prior 모터 0.4 (SimDist 계획기, 넘어짐 많음) | 0.40 | 0.65 | **0.45 / 0.46** |
| prior-first 정상 | 1.00 | – | 1.20(격자 끝) / **1.03**; 0.7 이상에서 평평 |
- v1(균등 가중, 전체 관측)은 리셋 과도 오차가 지배해 우도가 평평했다. v2는 상한이 걸리는 스텝만 세어 곡선이 선다: 0.35 이하에서 급상승, 0.45–0.55에서 최소, 그 위는 완만.
- **P10a**: 0.4 로그 → 0.50(경계 통과), 정상 로그 → 사후평균 1.03(통과; 0.7 이상은 상한이 안 걸려 원리적으로 구분 불가 — "약하지 않다"는 판정으로 충분). **P10b 성립**: 좁은 prior 로그에서도 0.45 — 히스토리 가시성 R² 0이었던 같은 축이 시뮬 되감기로는 정책과 무관하게 식별된다.
- 상향 편향(0.45–0.50 대 0.40): 식별은 effort_limit만, 평가 조건은 saturation_effort도 함께 스케일한 차이와 리셋 과도가 후보. 하드웨어(토크 상한 = PD 포화 하나)에서는 이 차이가 없다.

## 7. 결과 2차 (2026-10-30)
**P10d 식별 시뮬 데이터로 적응 (broadhead, 모터 0.4 평가, 넘어짐/1000)**
| 동역학 | 모터 0.4 | 정상 |
|---|---|---|
| broadhead 사전학습 | 1.49 | 0.38 |
| 식별값 0.5 시뮬에서 broadhead on-policy 45k로 적응 | **1.24** (0.84 [0.62, 1.11]) | 0.40 |
| 참값 0.4 시뮬에서 broadhead on-policy 45k로 적응 ("실데이터" 상한) | **2.74** (1.84 [1.25, 2.51]) | – |
- 식별 시뮬 데이터는 해치지 않고 조금 돕는다(n.s.). 뜻밖에 **참값 조건의 on-policy 데이터는 유의하게 해친다**. 데이터 내용이 다르다: 0.5 데이터는 30 에피소드 전부 완주(평균 1500스텝, 넘어짐 0), 0.4 데이터는 62 에피소드 평균 725스텝(넘어짐 다수). 가설: 넘어짐이 많은 데이터로의 동역학 적응이 계획기를 해친다(값 헤드 동결 + 넘어짐 구간의 잠재 궤적 학습). 학생 prior에서는 B′ = B0였으므로 prior 의존. 재현(시드)과 "넘어짐 구간 제외 적응" 대조가 필요 — 주장에 넣기 전까지는 관찰로만 둔다.

**P10e 3축 식별 (관절 채널만, 4대 × 60라운드)**
| 로그 (참값 모터/마찰/질량) | MAP | 사후평균 |
|---|---|---|
| combo 0.6 / 0.3 / 3.0 | 0.6 / 0.5 / 3.0 | 0.81 / 0.55 / 3.4 |
| 저마찰 1.0 / 0.15 / 0 | 0.9 / 0.5 / 0.0 | 0.88 / 0.50 / 0.3 |
| 모터 0.4 / 0.8 / 0 | 0.7 / 0.5 / 1.5 | 0.69 / 0.53 / 1.4 |
| 정상 1.0 / 0.8 / 0 | 1.1 / 0.3 / 0.0 | 1.02 / 0.36 / 0.1 |
- 질량은 네 로그 모두 맞춘다. 모터는 combo·정상에서 맞고 모터 0.4 로그에서 0.7로 치우친다 — 모터·질량 교환(약한 모터 ≈ 무거운 짐)이 3축 격자에서 드러남(표본도 1축의 1/4). **마찰은 전혀 식별되지 않는다**(네 로그 모두 0.3–0.5로 평평): 관절 공간 오차만 썼기 때문이고, 마찰은 미끄러짐(몸체 속도)에 나타난다. 조치: 몸체 선·각속도 채널을 두 번째 우도로 추가(설계: 관절 채널 = 모터, 몸체 채널 = 마찰·질량), 6대 × 80라운드로 재실행 중.

**P10e 2차 (관절 + 몸체 속도 채널, 6대 × 80라운드)**: 마찰은 여전히 네 로그 모두 0.5(평평·무정보), 몸체 채널은 모터·질량 추정을 오히려 흐린다(combo 모터 1.0, 정상 질량 1.5). **판정: 이 되감기 식별기로 모터(와 대략 질량)는 되고 마찰은 안 된다.** 마찰은 0.4 s 열린 루프 되감기 안에서 미끄러짐으로 거의 드러나지 않는다. 기본 설정을 관절 채널로 되돌림. 방법의 주장 범위를 "히스토리로는 안 보이지만 시뮬 되감기로는 식별되는 **액추에이터 축**"으로 한정한다 — 하드웨어 토크 상한이 정확히 그 축이다. 마찰은 Limitations.

**P10d 후속 (2026-10-30 14:30)**: 참값 0.4 데이터로 적응한 broadhead 동역학은 정상에서도 해롭고(0.52 대 0.38, 1.38 [1.14, 1.60]), 넘어짐 경계 윈도를 뺀 적응은 **더** 나쁘다(4.86, 3.26배). 즉 해악은 넘어짐 구간이 아니라 포화 동역학 자체를 학습하는 데서 온다(동결된 값 헤드가 포화 잠재 궤적을 잘못 읽는다는 가설; 학생 prior에서는 B′ = B0였으므로 헤드 의존). 식별 시뮬(0.5) 데이터는 안전했다. **결론**: broadhead에서 실데이터 동역학 적응은 이득이 없거나 해롭고, 식별 시뮬 데이터는 안전하다. 논문에서는 "커버리지는 prior, 적응은 선택적·식별 시뮬로"로 서술하고 이 현상은 관찰로 보고한다.

## 8. 다음: 식별 주도 prior (targeted) — 2026-10-30 착수
식별이 "모터 축, ≈0.5"를 주면 블랭킷 넓힘(0.3–1.1) 대신 **그 값을 덮는 폭**(0.3–0.7)으로 전문가·헤드를 학습한다. 비교: SimDist(좁음) / broadhead(블랭킷) / targethead(식별 주도). **예측 P10f**: 모터 0.4에서 targethead ≤ broadhead(1.49), 정상 보상에서 targethead > broadhead(0.0291; 넓힘 대가 감소), 마찰 0.15에서 targethead ≥ broadhead. 드라이버 `stage6_targethead.sh`(전문가 2.5 h + 데이터 + 헤드 2 h + 평가 2.5 h).
