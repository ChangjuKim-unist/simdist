# 설계 33: 두 벌 모델 + 정책 출발 + 실행 중 오차 전환 (2026-11-19 등록)

## 0. 배경

- 연구문제(`docs/research_problem_ko.md`): 커버리지 밖 조건에 적응하면서 이득·안전·보존을 함께 만족시키기.
- 설계 32-A: 가중치를 나누는 한 모델(토큰 + replay)의 이득은 새 학습 시드에서 재현되지 않았다(3칸 중 1칸). 보존은 재현됐다. 등록한 결정은 "그 레시피 위에 쌓지 않고, 가중치를 나누지 않는 두 벌을 처음부터 3시드로 등록"이다. 이 문서가 그 등록이다.
- 설계 32의 B부(정책 출발 + 실행 중 1스텝 오차로 전환)는 여기로 옮긴다. 사용자가 승인한 방향(2026-11-18)의 ②·③에 해당하고 아직 한 번도 폐루프로 돌리지 않았다.
- 지금까지의 근거:
  1. **동역학 fine-tuning은 이득이 있지만 잊는다.** 다른 범위 밖 조건에서 넘어짐이 사전학습의 1.2~4.7배(설계 29).
  2. **망각의 모양은 둘이다**(설계 30 §8.5, 등록 안 한 관찰). 모터 적응 모델이 빙판에 서면 출발에서 넘어지고, 이때 실행 중 오차에는 표시가 없다. 빙판 적응 모델이 모터 40 %에 서면 걷는 중에 넘어지고, 실행 중 1스텝 오차가 0.80~0.91의 비율로 문턱을 넘는다.
  3. **정책은 빙판 출발에서 넘어지지 않는다**(설계 25, 속도 0.9, 명령을 한 번에 줌). 출발에서 넘어질 확률이 정책만 0.07~0.10, 사전학습 계획기 0.30(넓은 DR)~0.84(논문). 빙판에 적응한 논문 모델의 계획기는 0.08이다(설계 29, 세 속도를 합친 값).
  4. **replay를 넣은 한 모델은 전환 없이 보존을 지킨다**(설계 32, 모델 6개 모두). 논문·모터에서 걷는 중의 이득도 전부 남고(1.00~1.39), 잃은 것은 출발의 이득이다(등록 안 한 분해).
- 3과 4를 합치면 "출발을 정책에 맡기면 replay 한 모델로 충분할 수 있다"는 가설이 나온다. 등록 안 한 분해에서 나온 가설이므로 여기서 새 시드와 함께 비교 팔로 등록해 확인한다. 설계 32의 판정은 그대로다.

## 1. 질문

- **Q-T.** 두 벌(가중치를 나누지 않음) + 정책 출발 + 실행 중 오차 전환이 세 학습 시드 모두에서 이득과 보존을 함께 지키나?
- **Q-R.** replay 한 모델 + 정책 출발(전환 없음)이 세 학습 시드 모두에서 이득과 보존을 함께 지키나?
- **Q-P.** 정책 출발은 출발의 넘어짐을 정책 수준으로 낮추고, 계획기로 넘겨받은 뒤의 걷기를 해치지 않나?

## 2. 시스템

칸은 설계 31·32와 같다: 모델 {논문, 넓은 DR} × 적응 조건 {빙판(마찰 0.15), 모터 40 %}. 학습 시드는 42, 43, 44.

### 2.1 모델

| 이름 | 만드는 법 | 시드 |
|---|---|---|
| S (시뮬 쪽 사본) | 사전학습 모델을 평소 조건의 시뮬 계획기 창으로 동역학만 fine-tuning. replay = 사전학습 창(0.5 / 0.5). 실제 데이터는 쓰지 않음 | 42, 43, 44 |
| A (적응 사본) | 같은 시드의 S에서 시작해 적응 데이터로 동역학만 fine-tuning. replay 없음 | 42, 43, 44 |
| replay 한 모델 | 사전학습 모델을 적응 데이터 + 사전학습 창 replay로 동역학만 fine-tuning (설계 32의 "토큰 없음 + 사전학습 창만") | 42(설계 32), 43, 44 |
| 동역학 fine-tuning (비교 대상) | 사전학습 모델을 적응 데이터로 동역학만 fine-tuning (SimDist) | 42(설계 29), 43, 44(설계 30에서 같은 레시피로 만들어 둔 체크포인트, 폐루프는 이번이 처음) |

- 모두 3000스텝, 변형은 `dyn`과 `dyn_replay`다. 두 벌의 구성은 설계 31 §5 셋째 줄에 등록한 그대로다(시뮬 계획기 데이터로 먼저 고친 모델 + 거기서 적응한 모델).

### 2.2 정책 출발

- 리셋 뒤 정지 구간(25스텝)이 끝나고 **125스텝(2.5초) 동안 정책 헤드의 행동을 실행**한다. 계획기는 계속 돌리고, 그 평균을 정책의 계획으로 덮어써서 넘겨받을 때 실행하던 계획에서 이어 가게 한다.
- 125스텝의 근거(이 설계 전에 있던 기록): 설계 29에서 계획기의 빙판 출발 넘어짐은 리셋 뒤 50~95스텝에 몰려 있고, 로봇은 125~150스텝에 명령 속도에 닿는다. 값은 하나만 쓰고 결과를 보고 바꾸지 않는다.

### 2.3 실행 중 오차 전환 (두 벌 시스템만)

- 매 스텝 A의 1스텝 잠재 오차(직전 스텝에 실행한 행동에 대한 A의 예측과 지금 관측의 차이, 64차원 노름)를 잰다. 누가 행동을 골랐든 A의 예측으로 잰다.
- 같은 에피소드의 **직전 50스텝 평균이 문턱 θ를 넘는 동안** 후보를 S의 점수만으로 고른다(같은 후보, 같은 계획기). 내려가면 A로 돌아온다. 정책 출발 구간에는 전환하지 않지만 오차는 쌓는다.
- **문턱:** 시드·칸마다 보정 주행 1회. A + 정책 출발(전환 없음)로 자기 조건을 2000스텝, 평가와 다른 로봇(속도 0.3/0.6/0.9 × 시드 21~26). 계획기가 실행한 스텝의 50스텝 평균 오차의 95번째 백분위수(`scripts/sim2sim/stage33_calib.py`). 95 %는 설계 30과 같다.
- 실기에서는 적응 뒤 자기 조건을 몇 분 더 걷는 것에 해당한다(로봇 18대 × 2000스텝 = 12분).

### 2.4 배치하는 시스템

| 시스템 | 걷는 중의 모델 | 출발 | 전환 |
|---|---|---|---|
| 두 벌 + 정책 출발 + 오차 전환 | A, 오차가 높으면 S | 정책 | 있음 |
| replay 한 모델 + 정책 출발 | replay 한 모델 | 정책 | 없음 |

비교 대상(같은 평가): 사전학습 계획기(설계 29), 동역학 fine-tuning 3시드(그대로, 정책 출발 없음), 정책만, 사전학습 + 정책 출발.

## 3. 측정과 기준

- 폐루프 방식은 설계 29·31·32와 같다: 로봇 18대(속도 0.3/0.6/0.9 × 시드 11~16) × 5000스텝, 1000스텝당 넘어짐, 로봇 단위 짝 부트스트랩(5000). 칸 기준의 문턱도 그대로다.
  - **이득 칸 통과:** 자기 조건에서 유지된 이득 = (사전학습 − 시스템) / (사전학습 − 동역학 fine-tuning) ≥ 0.70, CI 하한 > 0.40. 이득이 있는 3칸(논문·빙판, 논문·모터, 넓은 DR·빙판). **분모의 동역학 fine-tuning은 세 시드의 평균**이다(설계 32의 한계 4).
  - **보존 칸 통과:** 다른 범위 밖 조건에서 시스템 − 사전학습 ≤ max(0.3 × 사전학습, 0.15). 4칸.
- **G (이득):** 세 시드가 각각 이득 3칸 중 2칸 이상.
- **K (보존):** 세 시드가 각각 보존 4칸 중 3칸 이상.
- **시스템 통과 = G와 K 모두.** 시스템마다 따로 판정한다.
- 함께 적는 것(기준 없음):
  - 모든 팔의 스텝당 보상, 출발에서 넘어질 확률, 걷는 중 넘어짐(노출 시간 기준), 걷는 중 정책 이탈.
  - 전환이 물러난 비율: 자기 조건(잘못 물러남)과 다른 범위 밖 조건(물러나야 함).
  - 넓은 DR·모터 40 %의 자기 조건(이득 칸이 아님, 해가 없는지), 평소 조건(시드 42).
  - 정책만, 사전학습 + 정책 출발.
- 실행 순서: 시드 42의 보정 → 정책만, 사전학습 + 정책 출발 → 시드 42의 두 시스템 → 시드 43, 44의 보정과 두 시스템 → 동역학 fine-tuning 시드 43, 44 → 평소 조건. 뒤쪽이 빠지면 빠졌다고 적는다. 동역학 fine-tuning 시드 43, 44가 빠지면 분모는 시드 42 하나이고 그렇게 적는다.

## 4. 예측 (실행 전 고정, 괄호는 확률)

| # | 예측 | 확률 |
|---|---|---|
| H1 | 사전학습 + 정책 출발: 빙판에서 출발에 넘어질 확률이 두 모델 모두 0.15 이하 | 0.75 |
| H2 | 두 벌 시스템: G 통과 | 0.55 |
| H3 | 두 벌 시스템: K 통과 | 0.6 |
| H4 | replay 한 모델 + 정책 출발: G 통과 | 0.55 |
| H5 | replay 한 모델 + 정책 출발: K 통과 | 0.75 |
| H6 | 전환이 자기 조건에서 잘못 물러난 비율이 시드마다 4칸 중 3칸 이상에서 0.10 이하 | 0.6 |
| H7 | 전환이 다른 범위 밖 조건에서 물러난 비율이 시드마다 4칸 중 3칸 이상에서 0.5 이상 | 0.4 |
| H8 | 정책만: 모터 40 %에서 출발에 넘어질 확률이 사전학습 계획기(논문 0.29, 넓은 DR 0.12)보다 낮음(두 모델 모두) | 0.5 |

- H2·H4가 낮은 이유: 논문·모터의 출발은 정책이 맡는데, 정책의 모터 40 % 출발은 잰 적이 없다(H8). 이 칸이 떨어져도 나머지 두 칸으로 통과할 수 있지만 넓은 DR·빙판은 값이 작아 잡음(SD 0.09~0.23)에 민감하다.
- H7이 낮은 이유: 모터 적응 모델이 빙판을 걸을 때 실행 중 오차가 오르는지는 본 적이 없다(설계 30에서 본 것은 반대 방향 두 칸이다).

## 5. 결정 규칙

| 두 벌 시스템 | replay 한 모델 + 정책 출발 | 다음 |
|---|---|---|
| 통과 | 통과 | 둘 다 성립. 단순한 쪽(replay 한 모델 + 정책 출발)을 주 방법으로, 두 벌 시스템을 비교 팔로 둔다. 다음 설계 = 연구문제 §3의 비교 대상(시뮬 replay 비율, low-rank + anchor, 앙상블 벌점, 두 모델 최저 점수)과 새 평가 시드, 그리고 설계 19의 실기 조건 |
| 통과 | 불통과 | 두 벌 시스템이 주 방법. 같은 다음 설계 |
| 불통과 | 통과 | replay 한 모델 + 정책 출발이 주 방법(모델 하나, 전환 없음). 같은 다음 설계 |
| 불통과 | 불통과 | 떨어진 기준으로 갈린다. (a) 둘 다 G 불통과이고 잃은 이득이 출발에 있음 → 정책 출발이 적응 모델의 출발 이득을 버린 것. 출발 구간을 모델 쪽에서 다루는 판을 등록. (b) 두 벌만 K 불통과이고 물러난 비율이 낮음 → 전환 신호의 문제. replay 한 모델 쪽에서 G를 고치는 판을 등록. (c) 걷는 중의 이득이 사라짐 → 넘겨받는 순간 또는 S의 문제. 원인을 가르는 팔을 등록. 어느 경우든 다음 방법을 3시드로 등록한다 |

- H1이 틀리면(정책 출발이 빙판 출발을 못 고침) 정책 출발 자체를 다시 설계한다(명령을 천천히 올리는 출발과 비교).

## 6. 한계 (미리 적음)

- 시뮬 안의 두 조건(빙판, 모터 40 %)뿐이다. 빙판의 이득은 대부분 출발에서 온다.
- 평가 로봇은 설계 29~32와 같다(짝 비교). 정책 출발과 전환은 이번이 첫 폐루프라서 이 로봇들의 결과로 맞춘 값은 없다. 문턱은 다른 로봇(시드 21~26)에서 정한다.
- 정책 출발 125스텝, 창 50스텝, 95번째 백분위수는 각각 값 하나다. 민감도는 재지 않는다.
- S를 만드는 법은 하나다. S가 사전학습과 달라서 생기는 차이와 전환이 만드는 차이를 이 설계는 가르지 않는다(두 벌 시스템의 다른 조건 주행은 둘이 섞인 값이다).
- 두 벌 시스템의 "전환 없음" 팔과 동역학 fine-tuning + 정책 출발 팔은 없다. 정책 출발의 효과는 사전학습 + 정책 출발, 그리고 replay 한 모델 시드 42(설계 32의 정책 출발 없는 값)로만 따로 볼 수 있다.
- 보정 주행은 2000스텝이다. 문턱의 추정 오차가 잘못 물러난 비율에 그대로 들어간다.
- 로컬 스모크: 30스텝 학습(S, A, replay 한 모델)과 150스텝 폐루프 4런(보정, 정책만, 두 시스템; 논문·빙판), 분석 스크립트는 설계 32 결과를 이름만 바꿔 넣어 확인. 동작 확인용이고 결과로 쓰지 않는다.

## 7. 규칙

- 이 문서를 커밋·푸시한 뒤 실행한다. gpu1에서 `scripts/sim2sim/stage33.sh`, 결과는 `/mnt/newssd/cjkim/simdist/results/stage33`. 런당 11 GB 이하.
- 분석은 `scripts/sim2sim/stage33_gate.py`(실행 전 작성).
- 예상 시간: 학습 26개(S 6, A 12, replay 한 모델 8) 약 1시간, 폐루프 80런 + 보정 12런 약 19시간(GPU 4대). 시드 42의 두 시스템은 앞의 약 6시간에 끝난다.
- 아무것도 지우지 않는다. 결과를 보고 기준, 문턱, 팔을 바꾸지 않는다. 추가 확인은 새로 등록하거나 "등록 안 함"으로 표시한다.
