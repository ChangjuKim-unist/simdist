# 설계 문서 13: 맥락 조건부 월드모델 — ξ 슬롯 ψ (2026-11-04)

사용자 결정: "기존 월드모델 구조를 sim-to-real 격차를 깨기 좋게 개조" → "이 방향으로 가보자". 구조도·진단: https://claude.ai/artifact/NemgDz9aLQG8qh1RCfriXH. 드라이버 `scripts/sim2sim/stage11_context.sh`, 결과 `results/stage11/`.

## 1. 진단 (stage10 숫자, 1000스텝당 넘어짐)
현재 모델은 "로봇이 지금 어떤 상태인지"(모터 배율, 추가 질량 같은 느린 파라미터 ξ)를 어디에도 두지 않는다.
- 가치 V(z, c)는 현재 관측 한 장의 z만 본다 → 모터 0.4에서도 정상 가치를 줘 계획기가 공격적으로 간다. 동역학만 적응: 3.58 → 3.69.
- 동역학 f는 이력에 cross-attention하므로 ξ를 읽을 수 있지만 사전학습 데이터에 모터 축이 없었다 → 적응 = f 전체 재학습.
- prior π는 후보 450개 중 22개만 내는데 π만 바꾸면 결과가 4배 갈린다(SimDist 3.58, targethead 0.83/0.31) → 모델이 모르는 걸 π가 대신 안다.
- ξ 추정은 모델 밖 스크립트(5분 로그, 격자 재생)라 온라인 불가.

## 2. 구조 변경 (모두 `model.context.enabled` 뒤에 숨김; 꺼져 있으면 기존 모델과 동일)
- **맥락 인코더 g_ψ**: 입력 = 계획기가 이미 가진 이력(스케일된 관측 26×35, 행동 25×12 → 1210차원) → MLP [256, 256] → ψ (8차원). ψ[:3] = ξ̂ (모터 배율, 발 마찰, 추가 질량; 고정 상수로 표준화: 평균 [0.7, 0.7, 1.0], 표준편차 [0.23, 0.29, 1.15] = 각 DR 범위의 균등분포 통계). ψ[3:] = 자유 5차원.
- **주입**: (a) ψ → 선형(0 초기화) → 현재 상태 토큰 z_t에 더함(토큰을 하나 더 붙이면 0 초기화여도 softmax 키가 늘어 출력이 변하므로 더하는 쪽을 택함). 동역학 f와 정책 π는 이 토큰에 cross-attention. (b) 가치 V: value_emb([z, c]) + 선형(0 초기화)(ψ). 보상 R은 작업 정의라 그대로. 0 초기화라 go1_paper에서 이어 학습해도 첫 스텝은 기존 모델과 정확히 같다(CPU 테스트 `scripts/sim2sim/test_context_cpu.py`).
- **학습 시 ψ 노이즈** σ = 0.1 (RMA식 완충; 추론 땐 없음).
- **손실 추가** (`loss=world_model`): `context` = ‖ψ[:3] − ξ_s‖² (라벨 있는 창만), `context_consistency` = 같은 창의 미래 구간(o_t..o_{t+25}, a_t..a_{t+24})에서 뽑은 ψ와의 대칭 MSE(각각 stop-grad). 가중치 1.0 / 0.1. 나머지 항 그대로.
- **oracle 입력** `context_override` (B, 3): 있으면 ψ[:3]을 참 ξ_s로 덮어씀 (P2).
- **온라인 추정 로그**: 평가 스크립트가 ψ̂[:3]을 25스텝마다 기록 (P4).
- 계획기(MPPI)·하드웨어 노드는 변경 없음 (ψ는 모델 내부).

## 3. 데이터·학습 (사전 등록)
- 데이터: broadhead 전문가(`2026-10-20_07-40-06`, 모터 DR 0.3–1.1) + `system=go1dr` 기록 환경(모터 0.3–1.1 리셋마다, 질량 −1~+3 kg·마찰 0.2–1.2 시작 시), 384 로봇 × 50k 스텝 = 19.2M 스텝, physics 라벨 포함. 디스크 ≈ 55 GB(처리 후 여유 < 40 GB면 raw 삭제).
- 두 모델, 같은 설정으로 go1_paper에서 이어 학습(전체 헤드, 배치 128, 60k 스텝, lr 2e-4 → 5e-5):
  - `go1_ctx`: context.enabled=true
  - `go1_broadwm`: context 없음 (대조군: "데이터만 넓힌 효과")
- 평가: 고친 평가기(stage10과 동일, 6시드 × 3속도, 100 s). `results/stage11/eval_context.csv`.

## 4. 예측 (사전 등록; 기준 = stage10: SimDist 모터 0.4 3.58, targethead 0.83/시드2 0.31, broadhead 1.36, 정상 전부 0.00, SimDist 마찰 0.15 2.86)
| # | 비교 | 예측 |
|---|---|---|
| P1 구조 이득 | go1_ctx, 모터 0.4 | 넘어짐 ≤ 1.0 **이고** ≤ 0.6 × go1_broadwm |
| P2 추정 품질 분리 | go1_ctx oracle(ψ[:3] = 참값) 대 추론 | oracle ≤ 추론 ≤ 1.5 × oracle (모터 0.4) |
| P3 정상 무손해·대조군 | go1_ctx 정상 / go1_broadwm 모터 0.4 | 정상 넘어짐 ≤ 0.1, 보상 ≥ 0.0352 (SimDist −5 %); broadwm 모터 0.4는 1.0–2.0 (broadhead 1.36과 동급) |
| P4 온라인 추적 | 모터 0.4 → 0.8을 2500스텝에 전환, ψ̂ 모터 추정 | 전환 후 100스텝(2 s) 안에 추정 ≥ 0.6 (로봇 80 % 이상); 전환 전 500–2500스텝 평균 오차 ≤ 0.1 |
| P5 마찰 (탐색) | go1_ctx 마찰 0.15 | ≤ 2.0 이면 접촉 축도 ψ가 일부 읽음; > 2.86이면 못 읽음 (예측 아님, 기록) |

판정: P1·P3 성립 → 논문 주 주장을 "ξ 슬롯이 있는 월드모델"로 바꾸고 식별+덮기는 분포 밖 처리로 둔다. P1 실패 + P2 oracle도 ≥ 2.0 → 구조로 안 됨, 식별+덮기 유지. P1 실패 + oracle 통과 → 온라인 추정이 부족, 오프라인 식별값을 ψ에 넣는 혼합안(기존 식별 스크립트 + ψ 모델).

## 5. 비용·일정
데이터 ≈ 2.2 h, 학습 2 × ≈ 4 h, 평가 15회 ≈ 12 h → 약 22 h. stage9(설계 12)가 끝나는 11/5 밤 자동 시작 → 11/6 밤 종료. 폭 스윕 재평가(stage10 5단계)는 그 뒤로 미룸. 하드웨어 11/10 전 종료.

## 6. 선행연구와 새로움 (솔직하게)
맥락 변수 자체: CaDM(Lee 2020), RMA(Kumar 2021), Learning-to-Adapt(Nagabandi 2019). 우리 몫: 월드모델+샘플링 계획기+실기 사족보행에서 "가치가 ξ를 모르면 적응이 실패한다"는 측정(§1)으로 동기를 세우고, ψ의 사전학습 범위를 설계 12의 폭 규칙으로, 분포 밖을 식별+덮기로 잇는 것. 방법의 새로움은 중간, 발견과 이어져야 선다.

## 7. 위험
- **설계 5 관문 0(2026-10-21)의 반대 증거**: 넓은 DR 전문가의 RL 데이터에서는 25스텝 이력로 모터 배율을 선형 프로브로 못 읽었다(R² 0.004; 질량은 0.71–0.87). 그 데이터는 토크 요구가 낮은 "튼튼한 걸음"이었고, 식별 스크립트는 토크 요구 가중 구간에서만 맞혔다. 따라서 ψ의 모터 읽기는 요구가 높은 구간(속도 0.9, 포화)에서만 정확할 수 있다. 이번 데이터는 전문가 + 비전문가(초기 정책, 행동 노이즈) 혼합이라 포화가 더 잦지만, P4의 오차 ≤ 0.1은 속도별로 따로 본다(context_estimates.csv에 speed 열). 모터를 못 읽어도 P2의 oracle이 "읽기만 되면 구조는 충분한가"를 분리해 준다 → 그 경우 오프라인 식별값을 ψ에 넣는 혼합안.
- ψ가 마찰(접촉 때만 드러남)은 못 읽을 수 있음 → P5는 기록만.
- 정책이 ψ에 과의존해 ψ 오류 시 악화 → 학습 노이즈 σ 0.1.
- go1_paper 이어 학습이라 사전학습 분포(모터 1.0)에 편향 가능 → 대조군이 같은 조건이라 비교는 공정, 절대값은 보수적.
- 디스크 89 GB 여유: 데이터 55 GB. 체크포인트 3개 유지.
