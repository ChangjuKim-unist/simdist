# 설계 문서 12: DR 폭을 손이 아니라 예산 배분 규칙으로 (2026-11-03)

사용자 요청: "손으로 안 정하고 수학적으로 … 한정된 DR 예산을 어떻게 효율적으로 배분할지". 선행연구 조사(`reports/식별값 주변 DR 선행연구 조사.md`)의 결론: 식별 불확실성을 DR 폭으로 바꾸는 규칙은 어느 논문에도 없고, 다리 로봇은 전부 손 폭이다. 드라이버 `scripts/sim2sim/stage9_rule_width.sh`, 규칙 구현 `scripts/sim2sim/dr_from_posterior.py`. 총 ≈ 35 h GPU, 하드웨어 세션(11/10) 전 종료.

## 1. 규칙

DR은 분포 q(ξ), 총 질량 1이 **예산**이다. 어떤 조건에 질량을 얇게 깔수록 그 조건에서 성능이 떨어진다(측정: 폭 0.4 → 0.8이면 모터 0.4에서 넘어짐 0.43 → 1.49). 이를 손실 ≈ a·q(ξ)^(−k)로 두고, 식별 사후분포 p(ξ|로그) 아래 기대 손실을 최소화하면

> **q*(ξ) ∝ p_c(ξ)^(1/(1+k))**, p_c = 편향 보정된 사후분포.

단계: (1) 편향 보정 p_c(ξ) = mean_{b∈B} p(ξ+b), B = 시뮬 보정점의 MAP−참값 (leave-one-out: 0.5 헤드엔 {0.6, 0.8}의 {0.05, 0.10}, 0.6 헤드엔 {0.5, 0.8}의 {0.05, 0.10}; 0.3은 정찰 prior도 넘어져 제외). (2) 배분 q ∝ p_c^(1/(1+k)). (3) DR 범위 = q의 중앙 90 % 구간을 격자(0.05)로 바깥 반올림. 손으로 정한 상수는 90 %뿐이고, k는 E1에서 적합한다.

성질: 사후분포가 뾰족하면 좁게, 평평하면(식별 불가 축) 기존 블랭킷 그대로. "식별되는 축은 좁히고 안 되는 축은 넓게"가 같은 식에서 나온다.

## 2. 실험과 예측 (사전 등록)

| # | 실험 | 비용 | 예측 |
|---|---|---|---|
| E1 폭-비용 곡선 | 하한 0.3 고정, 상한 0.5 / 0.7(기존 targethead) / 0.9 / 1.1(기존 broadhead) 헤드 4개를 모터 0.4(전부 안쪽)에서 평가 → log 넘어짐 = log a + k·log 폭 적합 | 헤드 2개 ≈ 10.5 h + 평가 3 h | 넘어짐 단조 증가, **k ∈ [1, 2.5]**. 적합 실패(비단조 또는 k<0.5)면 기존 두 점의 k=1.8을 쓰고 표기 |
| E4 기준 평가 | targethead·broadhead·SimDist를 모터 0.5·0.6에서 평가 | 4.5 h | targethead ≤ 0.5, broadhead 0.6–1.2, SimDist ≥ 1.5 (0.5), ≥ 0.8 (0.6) |
| E2 규칙 헤드 | S2b 사후분포(broadhead 로그, 참값 0.5·0.6) → 규칙 범위 → 헤드 2개 → 참값·정상 평가 | ≈ 10.5 h + 3 h | 참값에서 넘어짐 ≤ targethead × 1.1 (CI가 1 포함), 정상 보상 ≥ targethead − 5 %. k=1.8이면 범위는 0.35–0.80 / 0.40–0.85 (k=1: 0.35–0.70 / 0.40–0.70) |
| E3 마찰 블랭킷 | 식별 없이 마찰 DR 0.1–1.2(모터 1.0) 전문가 → 헤드 → 마찰 0.15·정상 평가 | ≈ 5 h + 1.5 h | 마찰 0.15 넘어짐 ≤ 0.6 (S7 적응 0.52와 동급) 이면 "식별 불가 축은 블랭킷을 넓히거나 적응, 둘 다 됨"; > 0.8이면 "적응만 됨" |

판정 기준(넘어짐 = 1000스텝당, 6시드 × 3속도, 짝지은 bootstrap CI).

## 3. 규칙이 틀릴 수 있는 지점 (논문에 적을 것)
- 손실이 그 지점의 밀도에만 의존한다고 가정(이웃 조건끼리 기술 공유 무시). E1의 k가 이를 대신 흡수한다.
- 사후분포는 부트스트랩 z-score(최적 후보 대비 초과 오차 / 그 표준오차)로 정의해 온도 상수가 없지만, 모델 불일치(시뮬-실기 구조 차이)는 담지 못한다. 편향 보정과 p^(1/(1+k)) 평탄화가 완충이고, 보정점이 3개뿐이다. (§5: 2026-11-03 이전의 ε=0.1·중앙값 우도는 격자 의존이라 폐기.)
- E2가 targethead(손 폭 0.3–0.7)와 동급이면 "규칙이 손 폭을 재현·설명한다"가 결과이고, 더 나쁘면 규칙 기각 후 손 폭 유지·보고.

## 4. 제외한 것
토크 RFI 추가(모터 폭과 중복), 적재 축(S5 전제 실패), ξ-조건부 동역학(4월). 지연 측정은 11/10 하드웨어 세션 항목.

## 5. 코드 검토(2026-11-03)로 바뀐 것 — 모든 숫자를 다시 산출한다
세 영역 독립 검토 후 직접 재확인한 버그와 수정:
1. **평가 지표**: 지형 15 m + 테두리 20 m라 출발점 27.5 m 뒤에 땅이 없어 로봇이 떨어진 리셋이 "넘어짐"으로 집계됐다(정상 조건 0.40 = 전부 지형 끝). 수정: 테두리 100 m, `num_falls`(몸통·허벅지 접촉 또는 자세 이탈)와 `num_timeouts`를 따로 기록. 이후 넘어짐 = `num_falls`/5.
2. **평가의 모터 약화**: 평가는 토크-속도 곡선까지 곱해 학습 DR·하드웨어 캡(상한만)보다 가혹했다. 수정: 상한(effort_limit)만 곱함. 평가·데이터 수집·DR·식별·하드웨어가 같은 정의.
3. **식별 관절 순서**: 로그(Unitree 순서)와 시뮬 기본 자세(Isaac 순서)를 그대로 더해 되감기 시작 자세가 틀렸다. 수정: 인덱스 맵. 추가로 구간별 정규화 대신 전체 요구 가중 합, 넘어진 후보 구간 유지, 패딩 구간 제외, 사후분포를 온도 상수 없이 부트스트랩 z-score로 정의.
4. **"정상" 조건 물리**: 평가·식별 환경에서 PD 게인 ±10 %·관절 마찰 랜덤화가 켜져 있고 시드가 없었다. 수정: 끄고 시드 고정.
5. 하드웨어: 토크 상한이 1.0에서 꺼지던 조건(`<`→`<=`), Kd 1.0→0.5, 감시 타이머, 넘어짐 시 로그 종료, 분석 스크립트 ns→s, 매뉴얼 실행 명령에 `robot_config:=go1.yaml`.

재산출 체인 `scripts/sim2sim/stage10_reeval.sh`: 식별 로그 재수집·재식별(모터 0.3/0.5/0.6/0.8 × 두 prior, 마찰 0.15, 적재 5 kg) → SimDist 모터 축 적응 재수집·재적응 → 핵심 헤드 재평가 → 설계 12의 E1·k·E2·E3 → 폭 스윕 3시드 재평가. 설계 12의 편향 집합 B는 손 상수가 아니라 재식별 결과의 leave-one-out(MAP−참값)으로 자동 계산. 이전 결과 표(설계 문서 1–11)는 "수정 전 평가기" 표시로 남기고 논문에는 stage10 숫자만 쓴다. 예측은 §2 그대로 유지하되, 넘어짐의 절대값은 지형 끝 리셋(≈0.4)만큼 낮아지고 비율은 커질 것으로 본다.
