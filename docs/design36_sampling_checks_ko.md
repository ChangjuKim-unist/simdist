# 설계 36: MPPI 후보 분포에 대한 확인 세 개 (등록 2026-11-21)

## 1. 질문

조사 보고서(reports/MPPI 샘플링 분포 조사.md, 2026-11-21)는 "실측으로 고르는 행동 모드 + 모드 안의 좁은 국소 정제"를 추천했다. 그 방법을 만들기 전에 지금 planner의 샘플링에 대한 사실 세 개를 먼저 확인한다. 사용자 승인 2026-11-21("고고").

- **C1. warm start.** 코드(simdist/control/mppi_batch.py, mppi.py; upstream SimDist와 같음)는 직전 계획을 `roll(+1)` 한 뒤 1..T−1 스텝을 0으로 둔다. 남는 값은 0번 칸 하나(직전 계획의 마지막 스텝)뿐이라 사실상 warm start가 없다. 실행하는 행동은 계획의 0번 칸이므로 의도는 `roll(−1)` + 마지막 칸 0이었을 것이다. 고친 판이 과제 점수 S, 떨림, 넘어짐을 바꾸나?
- **C2. planner와 정책만 (기존 로그, GPU 없음).** 적응한 planner가 정책만보다 S에서 나은 조건이 있나? planner가 정책에서 벗어난 크기와 모델이 약속한 이득이 실제 결과와 관련이 있나?
- **C3. 후보 순위.** planner가 실제로 지나가는 상태를 고정하고, 그 스텝의 MPPI 후보들을 실제로 굴려 보면, 모델 점수 순위와 실제 결과 순위가 맞나? 높은 점수 꼬리를 누가 차지하나?

## 2. 조건과 모델

- 조건: 설계 34·35와 같다. 평지, 로봇 18대(속도 0.3 / 0.6 / 0.9 × 시드 11–16), 5000스텝. 평소, 끄는 짐 20 N(tow20), 모터 전체 50 %(mot50), 뒷다리 하나 50 %(legR50).
- 모델: 논문 모델(go1_paper), 설계 34에서 조건마다 적응한 모델(`go1_paper_<조건>_dyn_b45000_s42`).
- planner 설정은 지금 그대로(가우시안 450 + 정책 22, 반복 8, elite 64, 온도 0.25). C1만 warm start 방식을 바꾼다.

## 3. 확인 세 개

| | 돌리는 것 | 새로 재는 것 |
|---|---|---|
| C1 | init_mode = shift(지금 코드) vs shift_fwd(고친 판) × 다섯 칸: 논문 모델 planner로 평소·tow20·mot50, 적응한 모델 planner로 자기 조건 tow20·mot50. 두 판 모두 새로 돌린다(10개) | S, 넘어짐, 떨림(행동 2차 차분, 설계 27 `robot_metrics`), 정책 이탈 ‖a − a_pol‖, 옆 속도, 회전 SD. 매 스텝 elite ESS 비율(1/Σw²/64)과 정책 표본의 가중 몫(첫·마지막 반복) |
| C2 | 설계 34 로그(results/stage34/diag_*.npz)만 쓴다 | (a) 조건마다 정책만(POL)·적응 전 planner(PRE)·적응 뒤 planner(ADP)의 S. (b) PRE·ADP 런 안에서 걷는 중 50스텝 창마다: 모델이 약속한 이득 ΔĴ = (실행 계획 점수) − (정책 계획 점수), 정책 이탈 d, 실제 S·보상 |
| C3 | 설계 18 분기 도구(scripts/sim2sim/branch_eval.py)에 후보 묶음 M을 더한다. planner가 걷게 두고(drive = planner) 300스텝 이후 50스텝마다 상태를 저장하면서 그 스텝의 후보를 같이 저장한다. 저장 상태 중 조건마다 96개를 골라, 후보 64개(첫 반복 가우시안 24 순위 층화 + 정책 4, 마지막 반복 가우시안 24 + 정책 2 + 점수 상위 8, 실행 계획, 정책 head 계획)를 25스텝 개루프로 실행하고 정책 head로 100스텝 이어 간다. 실행 계획과 head 계획은 복제 3개(잡음 측정). 조건: 적응한 모델이 자기 조건 tow20·mot50·legR50, 논문 모델이 평소 | 점마다 모델 점수와 실제 125스텝 수익의 순위 상관(Spearman), 점수 상위 10 % 후보의 출처와 실제 결과, 실행 계획·head 계획·최고 점수 후보의 실제 수익 비교, 넘어짐 |

C1의 코드: `control.init_mode=shift_fwd` (mppi_batch.py). 진단 기록 ess_first / ess_last / pol_first / pol_last (simulate_batch.py). C3의 코드: branch_eval.py 묶음 M, 분석 scripts/sim2sim/stage36_rank.py. C2의 분석: scripts/sim2sim/stage36_logs.py.

## 4. 기준 (실행 전 고정)

S는 설계 35 §4 정의(목표 속도 기준 추종 + 다섯 벌점, 걷는 중 = 리셋 뒤 300스텝 이후). 비교는 같은 로봇끼리 짝, 95 % 구간은 로봇 18대 bootstrap 5000번(C3는 분기점 bootstrap).

| 확인 | 판정 |
|---|---|
| C1 "warm start가 중요" | 다섯 칸 중 하나라도 S 변화가 지금 코드 S의 2 % 이상이고 구간이 0을 제외, 또는 떨림 변화가 20 % 이상이고 구간이 0을 제외. 중요하면 이후 planner 비교(설계 37 이후)는 고친 판을 기준으로 다시 잰다. 아니면 지금 코드를 유지하고 기록만 한다 |
| C1 "진단 지표 채택" | 논문 모델 planner에서 정책 표본 가중 몫(마지막 반복, 걷는 중 평균)이나 ESS 비율이 평소와 어떤 조건 사이에서 2배 이상 다르면, 조건 변화를 알리는 지표 후보로 기록 |
| C2 "planner가 정책보다 낫다" | 조건마다 ADP S − POL S가 POL S의 2 % 이상이고 구간 하한 > 0 |
| C2 "약속한 이득에 정보 없음" | 로봇 안 창 단위 Spearman(ΔĴ, 실제 S)의 로봇 평균이 0.1 미만 (PRE·ADP 런마다) |
| C2 "벗어날수록 손해" | 로봇 안에서 d 상위 1/4 창의 실제 S가 하위 1/4 창보다 낮고 구간이 0을 제외 |
| C3 "안쪽 정제 유지" | 마지막 반복 후보 안 Spearman 평균 ≥ 0.3(구간 하한 > 0)이고, 실행 계획의 실제 수익이 head 계획보다 낮지 않음(차이 구간 하한 > −복제 잡음 SD) |
| C3 "넓은 가우시안 구름 제거" | 마지막 반복 Spearman < 0.1, 또는 점수 상위 10 % 후보 중 가우시안이 절반 이상이고 그 절반 이상이 head 계획보다 실제 수익이 낮음 |
| C3 그 밖 | "중간"으로 기록 |

## 5. 예측

- R1 (C1). 고친 warm start는 적어도 한 칸에서 떨림을 20 % 넘게 줄이지만, S는 모든 칸에서 2 % 안에서만 바뀐다.
- R2 (C2a). 적응한 planner는 다섯 조건 모두에서 정책만보다 S가 2 % 이상 높다.
- R3 (C2b). 약속한 이득 ΔĴ와 실제 S의 로봇 안 상관은 PRE·ADP 모두 0.1 미만이다. d 상위 1/4 창의 S는 하위 1/4보다 낮다.
- R4 (C3). 마지막 반복 Spearman은 네 조건 모두 0.3 미만이다. tow20과 mot50에서는 점수 상위 10 %를 가우시안 후보가 절반 이상 차지한다. 실행 계획과 head 계획의 실제 수익 차이는 잡음 안이다.

## 6. 결과를 읽는 법

| 결과 | 다음 |
|---|---|
| C1 중요 | upstream 버그로 기록하고, 이후 모든 planner 비교의 기준을 고친 판으로 바꾼다 |
| C2에서 planner가 어느 조건에서도 정책보다 낫지 않음 | 모드 안 국소 정제(r > 0)는 가치가 없다. 추천 방법의 안쪽 층을 다시 설계한다(보고서 §5 #5) |
| C3 "안쪽 정제 유지" | 추천 방법대로 모드 안 국소 정제를 남기고, 설계 37(모드 × 반경 격자)에 r > 0 칸을 둔다 |
| C3 "넓은 가우시안 구름 제거" | 설계 37에서 σ 2.0 전역 구름은 지금 코드 기준 한 칸으로만 남기고, 나머지는 국소 잡음만 쓴다 |
| C2 "정보 없음" + C3 Spearman < 0.1 | 점수가 가까운 후보끼리도 순서를 못 매긴다. 설계 37은 r을 실측으로만 고르고 r = 0이 유력 |

설계 37(모드 × 반경 격자, 보고서 §6 ④)은 이 결과와 설계 35 P1·P2를 본 뒤 따로 등록한다.

## 7. 한계

- C2는 관찰 자료라 창마다 상태가 다르다(ΔĴ가 큰 창은 원래 어려운 상태일 수 있다). 로봇 안 비교로 속도·로봇 차이만 지운다.
- C3의 후보는 25스텝 개루프로 실행한다. 실제 planner는 매 스텝 다시 계획한다. 모델 점수가 예측하는 것이 개루프 25스텝 + value라서 순위 검사로는 맞는 짝이지만, 폐루프 이득과는 다르다.
- C3 이어 가기는 정책 head(설계 18과 같음)다. planner로 이어 가면 비용이 수십 배다.
- 적응 모델은 학습 시드 하나(42).
- 하드웨어 planner(200 × 3)는 재지 않는다.
